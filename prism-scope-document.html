01Executive Summary

PRISM is a standalone, browser-based financial tracking system purpose-built for NTT DATA's fixed-bid SAP delivery portfolio. It replaces manual spreadsheet reconciliation with a structured month-end workflow covering project baseline capture, monthly effort submission by PMs, PD approval, Finance lock-down, and IFRS 15 percentage-of-completion revenue recognition.

PRISM is fully self-contained — it has no real-time integration with SAP, ERP systems, or external time-tracking tools. All monetary values are stored in local currency (THB); USD is a display-only computed value. The system covers 6 active projects across EMEA and APAC as of October 2025.

Core purpose: Ensure every recognised revenue figure is traceable to an approved EAC, a locked period, and a signed-off POC% — eliminating the risk of unreviewed month-end postings.

02System Overview & Purpose

What PRISM Manages

  • Project baselines — TCV, sold margin, phase Gantt, milestone invoicing plan, resource mix
  • Monthly EAC updates — PM enters revised ETC each period; system computes EAC and POC%
  • Revenue recognition — Percentage-of-completion method per IFRS 15; revenue = TCV × POC% − frozen prior YTD
  • Approval workflow — PM submits → Project Director approves → Finance locks
  • Portfolio analytics — Margin erosion, project health, backlog, AR ageing across 6 projects
  • Freelancer invoice reconciliation — Match system-booked days to received invoices before Finance close
  • Rate masters — FY-versioned L1–L7 internal cost rates + freelancer bands
  • Admin — Period calendar, countries & FX rates, user access management

Architecture Principles

  • Fully standalone — no SAP, ERP, or external API connections
  • Browser-based HTML/CSS/JS; no backend framework in prototype phase
  • All monetary fields stored in local currency (LC); USD computed at runtime via latest FX rate
  • Exceptions are system auto-generated based on configurable business rules (not manual flagging)
  • Immutable frozen periods — once a Finance lock is applied, no field in that period may be edited without an Admin reopen + full re-approval cycle

05Core Business Rules & Formulas

5.1 Revenue Recognition (IFRS 15 — Percentage of Completion)

POC %
POC% = Actuals to Date (LC) ÷ EAC (LC)
Revenue This Period
Revenue = (TCV_LC × POC%) − Frozen Prior YTD_LC
  • Actuals to Date — cumulative cost of all booked resources (own FTE + freelancers + fixed subcon) from project start through end of current period
  • Frozen Prior YTD — the locked cumulative recognised revenue from all prior closed & frozen periods; immutable once frozen
  • TCV — Total Contract Value, stored in local currency; set at baseline and never changed without a new baseline version

5.2 EAC (Estimate at Completion)

EAC
EAC = Actuals to Date + ETC (Estimate to Complete)
  • ETC is entered by the PM during monthly submission for Own FTE and Freelancer resources (remaining days × rate)
  • Fixed Subcontractor ETC is computed from fixed_price × (1 − completion_%); PM enters completion % only
  • EAC is locked per period once Finance closes; prior EAC values are preserved in the recognition history

5.4 Submission Workflow

  1. Admin opens the period (sets status → Open)
  2. PM enters ETC and subcon completion %, system computes EAC and POC%, saves as Draft
  3. PM reviews figures and clicks Submit — status → Submitted
  4. Project Director reviews on prism-05; can Approve, Hold with comment, or Reject
  5. If Rejected: PM must revise and re-submit
  6. If Approved: Finance sees submission on prism-06 and can Lock the recognition
  7. Finance lock: period status → Closed & Frozen; revenue figure posted to history
No alert() popups at any step. All validation feedback is inline within the screen.

5.6 Billing & Receivables Formulas

The following metrics are tracked on the portfolio dashboard and are available for Finance reporting:

Unbilled Revenue
Unbilled Revenue = Cumulative Recognised Revenue − Total Invoiced Amount
Accounts Receivable (AR)
AR = Total Invoiced Amount − Collections Received
  • Invoice data — entered manually by Finance against each project milestone; no SAP AR integration
  • Collection data — manually recorded when payment is confirmed by Finance
  • AR ageing exception — auto-raised when any open invoice exceeds 60 days without confirmed collection
  • Invoicing plan vs actual — milestone screen tracks planned invoice date & amount vs actual invoice date & amount vs forecast; variance is flagged in portfolio dashboard

06Currency & FX Rules

  • Storage currency — All monetary values are stored in local currency (LC) only. For the Thailand portfolio, LC = THB.
  • USD display — USD values are computed at runtime as LC ÷ latest effective FX rate and shown as display-only (never stored).
  • FX rate — Entered manually by Finance per country per month. Effective date is set explicitly. Current rate: 1 USD = 36.50 THB (effective 01 Oct 2025).
  • FX history — All prior FX rates are retained. Frozen periods are never restated — the USD display for a frozen period uses the current FX rate, not the rate at time of freeze.
  • TCV — Always in local currency. The "USD TCV" shown on screens is a display convenience only.
  • Rate masters — L1–L7 and freelancer day rates are stored in USD. On-screen and on-project cost calculations convert to LC using the effective FX rate at the time of baseline creation.
Display USD (any amount)
USD_display = LC_amount ÷ countries.fx_rate_per_usd (current effective)

08Constraints & Assumptions

#ConstraintDetail
C-01No ERP/SAP integrationFully standalone. All data entered manually by users. No real-time sync with SAP timesheets, billing, or FI modules.
C-02No alert() popupsAll user notifications, validations, and errors are rendered inline on the screen. No browser-native alert/confirm/prompt dialogs.
C-03Local currency storageAll monetary fields persisted in LC (THB). USD is computed at display time only.
C-04Immutable frozen periodsOnce Finance locks a period, no submission, approval, or recognition field in that period may change without Admin reopen + full re-approval.
C-05Rate master versioningBaselines reference the rate master version active at baseline creation. Changing a rate master does not retroactively affect existing baselines or EAC computations.
C-06Revenue methodPercentage of completion (cost basis) per IFRS 15. No other recognition method is supported.
C-07Resource typesThree types only: Own FTE (L1–L7, daily cost rate × days), Freelancer (band day rate × days), Fixed Subcon (fixed price, PM enters % complete only).
C-08Exception generationExceptions are auto-generated by the system (Option A). Users cannot manually create, edit, or delete exception rules.
C-09Analytics scopeThree analytics sections (cost roll-up, effort variance, EAC effort trend vs baseline) appear on project-level screens (prism-03/04/05) only — not on portfolio, finance, admin, or QC screens.
C-10Single active FX rateOne effective FX rate per country at any time. History is retained but only the latest effective rate is used for live USD display.

09Out of Scope

  • Real-time SAP integration (timesheets, FI postings, billing, AR)
  • Multi-currency contract TCV (TCV is always a single LC amount)
  • Time & Materials (T&M) project types — fixed-bid only
  • Resource forecasting beyond ETC (no resource availability / capacity planning)
  • Client portal or external access
  • Mobile-native application
  • Automated invoice generation (milestones trigger manual invoicing only)
  • GL / journal entry posting to any accounting system
  • Multi-company / inter-company consolidation
  • Tax calculation (VAT / WHT)
  • Payroll or HR integration
  • Excel upload for PM submissions — PRISM uses direct browser UI for all ETC and actuals entry. Excel upload templates are not in scope for v1; all data is entered through structured screen forms.
  • Freelancer fixed-cost engagement mode — Freelancers are tracked on a day-rate (T&M) basis only. Fixed-price freelancer contracts are not supported in v1.
  • SAP module-wise cost tracking — Cost and effort are tracked at project and resource-category level (Own FTE / Freelancer / Fixed Subcon). Per-module or per-workstream cost breakdown is not implemented in v1.
  • Automated email / push notifications (approval reminders, overdue submission alerts)
  • Scheduled automated report exports (timed PDF or Excel generation)
  • Detailed task-level project planning (issue, risk, or change request management)

12Design Decisions & Resolved Open Points

The following questions were open in the initial scope draft. All have been resolved and are binding design decisions for PRISM v1:

Open PointDecisionRationale
Will invoice, collection, and AR data be manually entered or integrated from ERP?Manual entryNo SAP/ERP integration in scope. Finance enters invoice and collection amounts directly via milestone screens.
Should the tool support multiple currencies?Single LC per projectAll amounts stored in local currency (THB). USD is display-only. Multi-currency TCV is out of scope.
Should one project support multiple contracts / change requests?One baseline per versionEach change request creates a new baseline version. Projects table references the active baseline. Prior versions retained for audit.
Should project costs be tracked by SAP module and phase in reporting?Phase only in v1Phase Gantt is tracked. Module-wise breakdown is out of scope for v1; can be added in v2.
Are actuals entered at named-resource level or only by category/level?Named-resource levelEach resource is a named row (e.g., "Arjun Mehta — Functional Freelancer"). Effort plan rows are per resource per period.
For freelancer fixed-cost engagements, what recognition logic applies?Out of scope v1Freelancers are day-rate (T&M) only in v1. Fixed-price freelancer mode deferred to v2.
Is month-end approval workflow required, and who are the approvers?Confirmed3-step: PM submits → Project Director approves → Finance locks. No bypass allowed.
Should audit trail and version history be maintained for all revisions?Confirmed — full auditaudit_log entity records every INSERT/UPDATE/DELETE across all 20 entities. Finance-locked records are immutable.
Are dashboards only in-app or also downloadable scheduled reports?In-app + manual exportAll dashboard data is viewable in-app. Manual export to Excel is supported. Scheduled/automated report generation is v2.
Should PM actuals input use Excel upload or browser UI?Browser UI onlyPRISM is a fully browser-based tool. All ETC, actuals, and subcon % inputs are via structured screen forms. No Excel upload in v1.

13Implementation Phases

Phase 1 — Core System (Current: v1)

All 15 screens (prism-00 through prism-13) covering the full month-end recognition cycle:

  • Project master & baseline setup (TCV, phases, milestones, resource mix)
  • FY-versioned rate masters (L1–L7 internal rates, freelancer bands)
  • Monthly effort submission by PM (ETC entry, subcon % completion)
  • Cost-based POC calculation and revenue recognition per IFRS 15
  • PD approval and Finance lock-down workflow
  • Milestone and invoicing plan tracking (plan vs actual vs forecast)
  • Freelancer invoice reconciliation (expected vs invoiced, matched / disputed)
  • Portfolio dashboard, margin analysis, QC exception auto-generation
  • Period history, frozen period ledger
  • Countries master, FX rate management, user & role management
  • Full audit trail across all entities

Phase 2 — Enhancements (Planned)

  • SAP / ERP integration for AR, billing, and collection data
  • Freelancer fixed-cost engagement mode
  • SAP module-wise and workstream-level cost tracking
  • Excel upload framework for bulk baseline and actuals entry
  • Automated email notifications (submission reminders, approval alerts)
  • Scheduled PDF report exports
  • Advanced analytics: drill-down, forecasting, trend analysis
  • Multi-project rollup for inter-company or multi-BU portfolios
Phase 2 scope requires explicit change request and re-estimation. No Phase 2 item should be assumed in the Phase 1 delivery.
